> We use access tokens to verify and authorize every request to the Finogates API.

**Every API request to Finogates must use HTTPS and be authenticated with an access token.**
Send your token in the `Authorization` request header, as `Authorization: Bearer <access_token>`.

## Get an access token

Copy your `client_id` and `client_secret` from the [Developer Panel](https://app.finogates.com/developer-panel). Then swap them for a token with [Exchange Client Token](/api-reference/auth/exchange-client-token). This is the only endpoint that does not need a token.

```curl Get an Access Token theme={null}
curl -X POST "https://<environment>/v1/platform/auth/token" \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "YOUR_CLIENT_ID",
    "client_secret": "YOUR_CLIENT_SECRET"
  }'

```

The token is in `data.access_token` in the response.

## Call the API

Send the token on every other request:

```curl Example Api Call theme={null}
curl -X POST "https://<environment>/v1/platform/users" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -d '{
    "first_name": "John",
    "last_name": "Doe",
    "phone": "+15551234567"
  }'

```

This example creates a user with a phone number only. A user needs an `email`, a `phone` in E.164 format, or both. See [Create User](/api-reference/users/create-user).

Use the correct credentials for each [environment](/get-started/environments). The wrong credentials or URL can cause authentication failures.

Keep your `client_secret` and access token secure. Never expose them on the client side.
