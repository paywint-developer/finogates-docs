We send each event as a JSON `POST` to your webhook endpoint. Every event has the same outer structure, called the envelope. The fields specific to each event are in `data`.

## Example

```json
{
  "id": "6f1d2c8e-4b7a-4e0f-9a51-2c3d4e5f6a7b",
  "type": "payment_intent.succeeded",
  "event_type": "payment_intent.succeeded",
  "created_at": "2026-10-13T09:15:22.481203+00:00",
  "data": {
    "intent_id": "5cd7a3c1-4b45-4148-b383-299553699745",
    "user_id": "b3a9b622-cc63-4d3c-aad6-2d8e29e6f9d4",
    "amount": 100.0,
    "currency": "USD",
    "status": 4,
    "status_code": 4,
    "status_name": "succeeded"
  }
}
```

## Envelope Fields

<ResponseField name="id" type="string">
  Unique event ID (UUID). We send the same ID on every retry, so use it to spot duplicates.
</ResponseField>

<ResponseField name="event_type" type="string">
  The event, as listed in [Event Types](/webhooks/event-types).
</ResponseField>

<ResponseField name="type" type="string">
  The same as `event_type`, except for payment events. For those, it shows the payment's current status. See [Payment Events](/webhooks/events/payment).
</ResponseField>

<ResponseField name="created_at" type="string">
  When the event was created (ISO 8601, UTC).
</ResponseField>

<ResponseField name="data" type="object">
  Fields specific to the event. We may add fields over time. Ignore any you don't use.
</ResponseField>

## Naming

Event names use dots: `<resource>.<action>`, or `<resource>.<sub-resource>.<action>`. For example, `user_kyc.approved` and `payment_method.bank.added`.

## Delivery

1. We send the event to every active endpoint subscribed to it.
2. Your endpoint [verifies the signature](/webhooks/signature-verification).
3. Your endpoint responds with a `2xx` status. We retry on any other result. See [Retry Behavior](/webhooks/retry-behavior).

Events may arrive more than once or out of order. Use `id` to spot duplicates and `created_at` to put events in order.
