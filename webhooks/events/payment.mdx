Every payment sends `payment_intent.*` events. This covers wallet funding, withdrawals, transfers and card charges.

## Events

| Event                              | Sent when                                                        |
|------------------------------------|------------------------------------------------------------------|
| `payment_intent.created`           | The payment is created.                                          |
| `payment_intent.validated`         | A card payment is submitted and held for review.                 |
| `payment_intent.approved`          | The payment is approved.                                         |
| `payment_intent.rejected`          | The payment is rejected during review.                           |
| `payment_intent.executing`         | The payment is sent for processing.                              |
| `payment_intent.succeeded`         | The payment completed.                                           |
| `payment_intent.settled`           | The funds settled.                                               |
| `payment_intent.failed`            | The payment failed. `failure_reason` says why.                   |
| `payment_intent.voided`            | The payment was cancelled before it settled.                     |
| `payment_intent.refunded`          | The payment was refunded.                                        |
| `payment_intent.charged_back`      | A chargeback reversed the payment.                               |
| `payment_intent.document_scanned`  | A document attached to the payment was scanned.                  |

## Data Fields

Fields that don't apply to a payment are `null` or left out.

<ResponseField name="intent_id" type="string">
  The payment ID. Some rejection and cancellation events send it as `payment_id`.
</ResponseField>

<ResponseField name="transaction_id" type="string">
  The transaction that moved the money, once there is one.
</ResponseField>

<ResponseField name="user_id" type="string">
  The user the payment belongs to.
</ResponseField>

<ResponseField name="source_wallet_id" type="string">
  The wallet debited. We also send `wallet_id` when it differs from `source_wallet_id`.
</ResponseField>

<ResponseField name="destination_wallet_id" type="string">
  The wallet credited.
</ResponseField>

<ResponseField name="payer_user_id" type="string">
  The user who pays.
</ResponseField>

<ResponseField name="payee_user_id" type="string">
  The user who receives the money.
</ResponseField>

<ResponseField name="amount" type="number">
  The amount in major units. For example, `100.0` for $100.
</ResponseField>

<ResponseField name="currency" type="string">
  ISO 4217 currency code.
</ResponseField>

<ResponseField name="status" type="integer | string">
  The payment status. When it is a number, we add `status_code` and `status_name` (see below). Approval and review events send a string, such as `approved`.
</ResponseField>

<ResponseField name="failure_reason" type="string">
  Why the payment failed, was rejected or was cancelled.
</ResponseField>

<ResponseField name="reference" type="string">
  For payments created through the unified payment API: the quote reference. We send it with `source_type`, `destination_type` and `destinations`.
</ResponseField>

## Status Codes

| `status_code` | `status_name`    |
|---------------|------------------|
| 1             | `pending`        |
| 2             | `pending_review` |
| 3             | `processing`     |
| 4             | `succeeded`      |
| 5             | `settled`        |
| 6             | `failed`         |
| 7             | `rejected`       |
| 8             | `voided`         |
| 9             | `refund_pending` |
| 10            | `refunded`       |

<Note>
When `status` is a number, the envelope's `type` is `payment_intent.<status_name>`. For example, `payment_intent.created` arrives with `type` set to `payment_intent.pending`. Use `event_type` to route events.
</Note>
